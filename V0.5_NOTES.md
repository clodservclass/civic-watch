# CIVIC WATCH v0.5 — Public surveillance program registry

## Delivered
- Searchable, mobile-responsive `/surveillance/registry` page; safe text rendering and filters for technology, jurisdiction, agency, vendor, and program name.
- Read-only `GET /api/surveillance/programs` and `GET /api/surveillance/programs/{uuid}` with reviewed citations.
- PostgreSQL migration `migrations/0002_surveillance_registry.sql` with privacy-gated publication views and source verification.
- No seeded real-world claims, invented camera locations, operational feeds, or public write routes.

## Database migration
Run `0001_records.sql` first, then `0002_surveillance_registry.sql`, manually, after approval of any database charges. Never run old `schema.sql` on the same database.

For the application runtime database user, grant only `USAGE ON SCHEMA public` and `SELECT` on `public_incidents`, `public_sources`, `public_surveillance_programs`, `public_surveillance_sources`, and `schema_migrations`. Do not grant access to underlying private tables. The migration role must be separate.

Until a DB is configured, `/api/surveillance/programs` returns an empty list with a no-database message. If the database is configured but migration 0002 is missing, the endpoint returns 503; `/ready` checks both migrations.

## Review and publication policy
All records default to unpublished and sensitive. Only records marked verified, human-reviewed, non-sensitive, published, and supported by at least one independently verified source appear in public views. **The schema is not a substitute for an authenticated moderation workflow**; do not publish real entries before review tooling and audit enforcement are implemented. Source verification is a claim by a reviewer, not automated fact-checking.
